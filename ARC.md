# sglang-arc-2: arc-forge's private sglang fork

Upstream [sgl-project/sglang](https://github.com/sgl-project/sglang) `v0.5.20` (`94602c9c`) plus arc-forge's changes.
Each commit is one change. The early changes were rebuilt one by one from arc-forge's `patches/`, and their commit messages name the source patch file and its sha256.
All later sglang changes are committed directly here; arc-forge's `patches/sglang-*` is frozen.

Which commit a deployment target points at is decided by arc-forge's `deploy/sglang.lock.json`; the maintenance tools are in arc-forge's `work/sglang_fork/`. Remote machines (Colab, Runpod, Kaggle) don't clone this private repo; they use the tarball exported by `export_tree.py`.

## How platform differences are handled

The same commit runs on every platform; differences are dispatched by flags or by GPU architecture, and the defaults keep the original behavior:

- **Masking the padded vocab** (`ARC_LOGITS_VOCAB_LIMIT=<N>`, 2026-10-11, opt-in; behavior unchanged when unset):
  - LogitsProcessor sets the logits of ids ≥ N to −inf. Normal sampling, spec verify's rejection sampling (including the path where `ARC_RS_FUSED_SOFTMAX` computes directly from the logits) and logprobs all come after this, so none of them can produce these ids.
  - Purpose: Qwen3.8-FN's lm_head has 248320 rows, but tokenizer ids only go up to 248077. Untruncated T=1.0 sampling drew 248134 once in about 8.9e7 RL output tokens, and arc-forge's ledger audit (`ids_in_vocab`) rejected the whole batch because of it.
  - If N is larger than the model's vocab_size, server start-up raises.
  - The drafter side needs no change: when it proposes a padded id, the target probability is 0, so rejection sampling never accepts it.
  - Test: `test/registered/unit/layers/test_arc_logits_vocab_limit.py`.
- **Default temperature for Responses** (`ARC_RESPONSES_DEFAULT_TEMPERATURE=<T>`, 2026-10-11, opt-in; behavior unchanged when unset):
  - When a `/v1/responses` request sends no temperature, T replaces the class default 0.7. A value the request sends itself, and the generation_config under `--sampling-defaults model`, still take precedence.
  - Purpose: codex never sends a temperature, so this flag is the only way for RL rollouts to sample at T=1.0 (arc-forge `configure_b200.py --rollout-temperature`).
  - `--preferred-sampling-params` cannot change this value: Responses always fills in the temperature itself.
  - A value that is not a finite number ≥ 0 raises at import. Test: `test/registered/unit/entrypoints/openai/test_responses_protocol.py`.
- **HiSparse L4 path** (h23–h39: attention DP2, sm_89, distributed spec, native MTP host KV):
  - All controlled by flags such as `ARC_HISPARSE_*`, `ARC_GDN_STATE_FMT`, `ARC_NATIVE_MTP_KV_HOST`, or reachable only on sm_89 / DP / TP>1.
  - G4 (TP1) with all L4 flags off is bit-identical to v8: prefill logprobs of 12 real prompts plus 512 decode steps all match; see arc-forge `work/sglang_fork/`.
- **HiSparse session replay of the own last turn** (`qsa_session_replay_own_last_turn` in `hisparse_config`, requires `qsa_session_replay`, off by default): uses the same check as h14's `replay_request` (`managers/replay_own_turn.py`); the generated range is the record's `[prompt_len, gen_end)` (`output_ids_through_stop`: under spec the record holds extra accepted draft ids after the stop, which don't count); after codex rewrites the previous turn, the next request still resumes at P without letting go of the record. Only generations that ended with stop/length are taken over (partial outputs parked by abort/retract are not; skip reason `aborted`). **sticky**: codex rewrites that message the same way in every later turn, so each takeover leaves an entry in the record (`rec.own`), and when a later request sends bit-identical ids for that message, the record's ids are swapped back in again (span `sticky: true`); a request carries the entries its ids hold at intake, hands them to the record when parked, and they are dropped when the record is truncated/released (arc-forge `docs/plans/replay_own_last_turn.md`). Counters `replay_own_turn`/`replay_own_turn_closure`/`replay_own_turn_sticky`/`replay_own_turn_entries`/`replay_own_turn_sticky_drop_<why>`/`replay_own_turn_skip_<why>` (in the session cache stats at idle); spans in the `QSA_REPLAY` log line.
- **DFlash** (`ARC_DFLASH_DRAFTER=<export dir>`):
  - A single worker: the drafter runs on this card's attention-TP group.
  - The routed experts pick a backend by compute capability by default: sm_100/sm_120 use CUTLASS W4A4; sm_89 uses Marlin W4A16, with EP inside the group.
  - lm_head: `TargetHead` on a single card, `PairHead` when the group is larger than 1.
- **B200 (sm_100)** (arc-forge `docs/research/sglang_fork_b200_20261005.md`):
  - DFlash with a group larger than 1 defaults to `ARC_DFLASH_COMPILE=det`: each rank's torch.compile autotunes on its own and picks different kernels, so the proposals diverge.
  - NVFP4 KV plus HiSparse uses sm_100's trtllm-gen gather; upstream allows only the triton/trtllm_mha/fa4 attention backends for hybrid GDN.
  - 0004's distributed MTP top-1 doesn't support attention DP and raises at server start-up (`SGLANG_QWEN4_MTP_DISTRIBUTED_TOPK1=0`).
- **rejection sampling**: the draft decode graph's `draft_probs` are cloned before verify (`c70c0178`); applies to every platform.
- **TITO session ledger** (all opt-in, arc-forge `docs/plans/tito_session_ledger.md`): `--session-replay` makes the TokenizerManager record, per `session_id`, the exact tokens the model saw and sampled, and swap ids the client re-tokenized back to the sampled ids; `--session-ledger-dir` (`-all`/`-logprobs`/`-routing`) writes it to disk. `--session-replay-empty-think`: also swaps back the sampled ids when the client renders the previous assistant turn's non-standard empty thinking as the standard `<think>\n\n</think>\n\n` (span `kind: empty_think`). `--session-replay-own-last-turn`: for the message of the session's last generation, the model's own sampled ids are authoritative — replay used to stop at that message (`text_differs`: tool calls truncated by the budget, broken calls normalized by the parser, truncated thinking with `</think>` added by the template) and now swaps the sampled ids back in; a truncated generation with no stop is followed by a closure (the text after the client's truncation point, or the template's think closure), which counts as prompt, not generation (span `kind: own_turn`, arc-forge `docs/plans/replay_own_last_turn.md`). **sticky**: codex rewrites that message the same way in every later turn, so a taken-over message leaves an entry with S, and when a later request sends bit-identical ids for it, the sampled ids are swapped back in again (span `sticky: true`); if the client sends other ids, the entry is dropped and it is text_differs as before; entries are dropped on segment split, close and evict. Old messages that the client really changed are left alone. f7 offline: all 2,449 requests extend S (0 rewinds, 0 segment splits; 13 rewinds with the flag off). `--no-mm-literal-image-sentinel`: a literal `<image>` in chat/Responses traffic is text.
- **routed experts**: `flashinfer_trtllm` is now written by the kernel's `routing_replay_out` (it used to return all zeros); int16; the host buffer is built only on the rank that sends output; `meta_info` carries `routed_experts_meta` (dtype/shape/start), and **clients always decode by it**.
- **Token-id requests with video are no longer re-tokenized**: upstream `SGLANG_MM_AVOID_RETOKENIZE` (#26555) keeps the client's ids only for image-only requests; with video it uses the result of re-tokenizing after the processor decode, so non-standard tokenizations drift silently. qwen3-vl/qwen3.5/qwen4_exp now always keep the client's ids and only splice the media blocks the processor expanded (video = timestamped groups) into the placeholders (`base_processor.splice_timestamped_media_blocks`); a mismatch is an error, with no fallback to re-tokenizing.
- **Media ids in Qwen4 PLE** (`--ple-mm-placeholder-ids`, opt-in, upstream behavior by default; arc-forge `docs/research/qwen38fn_ple_mm_clamp_20261007.md`): `embed_mm_inputs` clamps the radix pad hashes in place to vocab_size−1, and PLE afterwards reads the same `forward_batch.input_ids`, so every image/video position reads 248319; HF, vLLM and llama.cpp read `<|image_pad|>`/`<|video_pad|>`. With the flag, the model declares `mm_media_token_ids`, and before the clamp the media positions are rewritten to their placeholders by a scatter with the same mask. The context between chunks, the n-gram history of the radix cache and the HiSparse session cache, and the n-gram ids gathered by DP attention all come from this tensor and change with it. Pure torch, in the same place on every platform. Batches mixing precomputed/encoder inputs, and EVS, raise.
- **DFlash**: requests that end after prefill alone also free their draft state (`0d808d613`; previously about 70 `max_new_tokens=1` requests on an idle server would bring down the scheduler).
- **Runtime VRAM** (arc-forge `docs/research/g4_runtime_vram_headroom_20261005.md`; G4 c110, 0.92, real games, minimum free device memory 0.84 → 3.19 GiB):
  - The extend batches of PLE short conv are no longer padded to (requests, longest row, channels) but use `kernels/ops/qwen4_ple_varlen.py`, bit-identical to the padded version; PLE forward intermediates are freed right after use, and the residual and mask go in-place (bit-identical). All platforms, no flag.
  - Qwen3-VL vision: at most `ARC_VIT_MAX_PATCHES` (default 16384) patches per ViT forward, at most `ARC_VIT_MLP_ROWS` (default 8192) rows per MLP chunk; `0` goes back to computing everything at once. Same math, not guaranteed bitwise.
  - Decoded video frames are pinned only when `--mm-feature-transport` is `cuda_ipc`/`cuda_vmm`; with `cpu` the tokenizer process doesn't pin, so it no longer opens an extra 550 MiB CUDA context on the GPU.
  - When the DFlash group has a single rank, the drafter graph goes into the target's graph pool and is captured on the target's capture stream (`ARC_DFLASH_SHARED_GRAPH_POOL=0` turns this off); L4's attention-TP pair keeps its own pool.
- **dense DFlash drafter** (merged from `exp/dense-dflash`): when the drafter export's config has `ffn_type: dense_shared`, the routed experts are replaced by one dense SwiGLU (block FP8), without keep/calib (`ARC_DFLASH_KEEP`/`CALIB`/`MOE` must be unset); on the L4 pair the attention heads are split and the dense FFN is replicated.
- **Stability and speed for hs110 (G4 c110, dense10240 DFlash K=8)** (arc-forge `docs/research/hs110_c110_dense10240_k8_20261006.md`):
  - `ARC_MM_RELEASE_AFTER_PREFILL=1` (opt-in, default 0): a request's multimodal features (fp32 pixels on CPU) are freed as soon as its prefill completes. codex resends the screenshots of the whole history every turn; at c110 the scheduler's host RAM growth goes from about 9.6 to 1.3 GiB/h. A retracted request first parks in the scheduler, and the tokenizer reprocesses the items that lack features before it is requeued (see retract feature refill below).
  - `ARC_DFLASH_DRAFT_VOCAB=<{"ids": [...]}>` (single card): the drafter head computes logits/top-k only for these ids (`heads.SubsetHead`); this affects only the proposals, and the output distribution is guaranteed by rejection sampling; G4 c110 K=8 draft 16.3 → 12.6 ms, accept unchanged.
  - Value-preserving sync removals: `embed_mm_inputs`'s placeholder ids, the HiSparse prefill→decode batch and the mamba pool alloc go pinned and non-blocking; scalar assignments to CUDA tensors become `fill_`/`index_fill_` (DFlash state pool, HiSparse coordinator/pool); QSA extend metadata also gets a host max-position upper bound for multimodal batches (M-RoPE positions never exceed the token index). No throughput difference (within noise); kept because it removes per-request stream syncs.
  - `ARC_PLE_NVFP4=1` (opt-in, default 0; supports only `--ple-offload-backend pinned` + an FP8 PLE table): at load time the PLE table is quantized on GPU, shard by shard, to NVFP4 (e2m1 + one e4m3 scale per 16 values, no global scale since the source is already e4m3), 90 B per row stored contiguously, host 47.7 → 26.8 GiB. gather decodes to bf16; relative to the FP8 rows relRMSE 9.6%, cosine 0.9955; on a 4090 the gather is 15% faster than FP8. It errors out if not every row was loaded. `models/arc_ple_nvfp4.py`.
  - `ARC_PLE_INT5=1` (opt-in, default 0; mutually exclusive with `ARC_PLE_NVFP4`, and enabling both raises at server start-up; likewise supports only `--ple-offload-backend pinned` + an FP8 PLE table, and the width must be a multiple of 16): the same load-time GPU quantization, storing symmetric INT5 instead (groups of 16, one e4m3 scale per group = amax/15, codes −15..15 stored in 5 bits as code+16, 8 codes in 5 bytes, little-endian, contiguous); a row is d·5/8 code bytes followed by d/16 scale bytes, stored contiguously (110 B for d=160), host 47.7 → 32.8 GiB. gather decodes to bf16 (exact). EAN320 layer 1 shard_7, first 400k rows: relative to the FP8 rows relRMSE 4.17% (NVFP4 9.59%), cosine 0.99915; B200 pinned, 20M rows, random gathers of 15.8k/131k/524k rows: FP8 150/1,158/4,638 us, NVFP4 117/890/3,536, INT5 128/996/4,074. `models/arc_ple_int5.py`, tests `test/registered/kernel/embeddings/test_arc_ple_int5_codec.py` + `test_qwen4_ple_offload.py`.
  - `ARC_MM_LAZY_MEDIA=1` (opt-in, default 0; Qwen3-VL family, single tokenizer worker): images/videos already seen are no longer preprocessed again, and their pixels are not sent. The frontend remembers, by content (h41 artifact key), the token block, pad span and grid that each media item expands to in the processor; a request runs the processor only on media not seen before (one call, containing only their placeholders), splices the cached blocks of the other media into the tokenize result, and sends metadata-only lazy items. When the scheduler schedules a prefill and a lazy item falls inside the extend (prefix evicted, or prefix stopping before it), it sends the request back to the tokenizer before allocating anything (`ArcMmRematerializeReq`, carrying the hashes of every item in this extend), and the tokenizer fills in their pixels and resends it; ids/hashes don't depend on whether pixels are present, so the prefix still hits. Video (one offset per frame group) goes through the per-item embedding path, encoding only the videos that overlap the extend. A retracted request is requeued after its features are refilled (see retract feature refill below). `ARC_MM_LAZY_MEDIA_MIN_SEEN` (default 1): how many earlier requests must have carried an item before it is sent lazy; `ARC_MM_LAZY_MEDIA_ENTRIES` (default 16384). 4090 Qwen3.5-4B, 3 videos + 3 images, 17 turns: prompt ids and greedy output identical turn by turn (including a flush midway), frontend CPU 54.2 → 7.9 s. `multimodal/arc_lazy_media.py`.
  - retract feature refill (`65b0d354d`): when a request whose features were freed (`ARC_MM_RELEASE_AFTER_PREFILL=1`) or that has lazy items is retracted, it no longer raises (previously the whole server went down); it parks in `Scheduler.arc_mm_refill_parked` (holding no resources and keeping the tokens already output) and sends `ArcMmRematerializeReq(refill=True)` to the tokenizer; the tokenizer reprocesses it with pixels and sends back a request with `arc_mm_refill=True`, and the scheduler takes only the features of the items missing them (hash, modality, pad value and span length must all match, otherwise that request is aborted with an error), then requeues it as retracted. A client abort while parked is cleaned up the same way as for a request in the queue. G4 hs110 `SGLANG_TEST_RETRACT` 20 min: all 17 retracts refilled, 0 Tracebacks.
- **DFlash/QSA/extend changes of 2026-10-08** (arc-forge `docs/research/sglang_five_opt_20261008.md`; G4 c110, dense10240 acc-v4 FP8 drafter, K=8, 20 minutes of real games per arm, 0 Tracebacks in every arm):
  - The drafter's prefill ids are taken before the target forward (`DFlashDraftWorker.prefill_draft_ids`; always on, no flag). The target's mm embed rewrites the media positions in place (to vocab_size−1, or to the `--ple-mm-placeholder-ids` placeholder). On the deployment path the eager runner first copies input_ids into its own buffer, so the drafter was already reading `<|image_pad|>` and its input is bitwise unchanged; `SGLANG_EAGER_INPUT_NO_COPY`, `--enable-pdmux` and the full prefill CUDA graph share the same tensor, and on those paths the drafter used to read 248319/`<|video_pad|>`. `draft_ids` of `_draft_extend_for_prefill` is required; leaving it out or a shape mismatch raises.
  - `ARC_DFLASH_EXACT_PREFILL=1` (opt-in, default 0): the drafter state depends only on the last `receptive` = layers × (window + 3) positions (5,135 for acc-v4), so prefill refreshes only the last receptive positions of the prompt: a continuing chunk uses append, a chunk lying entirely before the tail keeps only its last GR, and the new window starting at the tail uses the real preceding GR. The result equals refreshing everything at once (float64 oracle; differences of about 1e-12 across chunkings). A resumed prefix whose history never went through the drafter still bootstraps from the chunk end as before (counter `bootstrap`).
  - `ARC_DFLASH_SESSION_PARK=1` (opt-in, needs `ARC_DFLASH_EXACT_PREFILL=1`, otherwise server start-up raises): when a session request ends, its drafter slot is not freed but parked under the session_id; the next request of the same session takes it over when the ids at every position the window read are identical (media positions compare pad hashes), appending only the part after the window. Only requests whose prompt's last chunk was processed register for parking: a request that ends between chunks (abort) may have a window that starts at the tail of the whole prompt with no history before it, so it is freed directly; an unregistered session request entering decode raises. When slots run out, the oldest parked slot is reclaimed; no extra VRAM is allocated. Every 200 extend batches it prints a line `DFlash exact prefill: {...}` (takeovers and the reasons for misses). G4 (a version before the registration-rule fix, which differs only for requests that ended midway through the prompt): 2,494 parks, 2,430 takeovers (97.4%), misses only gap 5, ids 1. Limits: under attention DP, a session that moves to another DP rank can't take over (`park_none`); `/close_session` doesn't free the parked slot immediately, LRU reclaims it.
  - `ARC_DFLASH_SPARSE_Q=1` (opt-in, default 0; needs `--speculative-use-rejection-sampling`, otherwise server start-up raises): rejection sampling's q is no longer scattered into a dense `[max batch, K−1, vocab]` FP32 buffer (0.71 GiB at c110 K=8, allocated before the target sizes its KV budget), but kept as each position's selector candidate ids and probabilities `[batch, K−1, 16]` (`eagle_info.SparseDraftProbs`), and the dense buffer is not allocated; verify goes through `reject_sampling.chain_speculative_sampling_sparse_q_triton`, with the same accept/residual/inverse-CDF arithmetic as the dense kernel (including the old behavior of returning V−1 when the residual is zero); on G4 the deployed shape (110×8×248,320) and graph replay with alternating batches are bit-identical to the dense kernel; untested on L4. G4: state pool 2.00 → 1.29 GiB, KV device rows +3.4% at the same memfrac. At the same memfrac the saved bytes turn into KV; to turn them into headroom instead, lower memfrac by about 0.0075 (0.71 GiB / 95 GiB) at the same time. The dense path of native MTP/EAGLE is untouched.
  - QSA verify tools (all opt-in, behavior unchanged when unset): `ARC_QSA_SELECTION_STATS=N` + `ARC_QSA_SELECTION_STATS_LAYERS=3,23,47` measure the selection overlap among the K rows of one request over the first N TARGET_VERIFY forwards and print a line `ARC_QSA_SELECTION_STATS {...}`; the stats op is recorded into the verify graph and keeps running afterwards, so use it only for debug runs. G4 K=8: the fraction shared by two adjacent rows (g2 common_fraction) is 0.79/0.74/0.83 (layer 3/23/47), short of the 0.85 threshold, so no grouped kernel with a shared history was built. `ARC_QSA_DIRECT_TILE_TABLE=<json>`: h22's direct decode looks up measured tiles by exact shape (format and checks in `qsa/direct_tiles.py`); when unset, the two built-in tile sets for G4 and sm_89 are unchanged; no fully measured table exists yet.
  - `ARC_EXTEND_TELEMETRY=1` (opt-in, `ARC_EXTEND_TELEMETRY_INTERVAL_S` default 60): each extend batch records one CUDA event and a host time before and after the target and after the drafter refresh (no sync), and each interval prints an `ARC extend telemetry` line: target/refresh GPU and CPU ms binned by (requests × new tokens), plus the prefill delayer's release reasons (an expired ms cap is recorded separately as `wait_ms_cap`). MIXED batches raise. Verified only on G4 TP1: under attention DP, if a decode-mode batch enters the extend branch because of `is_extend_in_batch`, `batch_shape` raises; do a short run before turning it on for L4. `managers/arc_extend_telemetry.py`.
- **RL weight sync** (`rl/v1`; arc-forge `work/qwen38fn_rl/SPEC.md` §6, §8): `keep_identity` of `update_weights_from_disk` (opt-in) writes only the directory's tensors into the model being served and leaves the served name/model_path/`model_config.model_path` alone; a failure midway is not dressed up as a rollback but marked poisoned (all requests aborted, generate returns 503 until the next successful keep_identity); with `flush_cache`, every rank must be idle or the request is refused untouched, and without flush it can sync midway through `pause_generation(in_place)`; refused under speculative decoding. `/model_info` gains `weights_source`, `poisoned` (bool) and `weights_poisoned` (reason or null). Every `update_weights_*` does one device sync before and one after writing the weights (under overlap, batches issued before the pause may still be on the forward stream); on the disk path a failed flush returns `success=False` instead of asserting.
- **routed-experts sentinel** (`rl/v1`): the host buffer and the device rows of every target forward start at −1 (`ROUTING_UNWRITTEN`), so rows the capture didn't write no longer read as expert 0 or as the values of the KV slot's previous owner; when a request finishes with a −1 or all-zero row → that request returns no routing, `meta_info["routed_experts_error"]` explains why, and the server doesn't die (a row-count mismatch still raises: that is the server's own bookkeeping error). Layers without a capture site (dense layers) return −1, no longer 0. TITO ledger appends record `weight_versions` (the version ranges of the generated tokens), and routing that the server rejected is recorded as `routing_error`.
- **G4 throughput changes of 2026-10-08** (arc-forge `docs/research/qwen38fn_dflash_g4_c110_throughput_20261008.md`; G4 c110, dense10240 acc-v4 FP8 drafter, K=4, 20 minutes of real games per arm, 0 Tracebacks in every arm; all three opt-in, behavior unchanged when unset):
  - `ARC_GDN_HOST_CHUNK_INDICES=1` (`check` also recomputes every plan with the old algorithm and raises on a difference): the GDN backend's `init_forward_metadata` computes chunk prefill's chunk indices and chunk offsets in numpy from `extend_seq_lens_cpu` (chunk 64, plus the BT for `chunk_fwd_o` for batches of 64 tokens or fewer) and sends them to the GPU non-blocking from pinned memory, and `fla/index.py` returns them directly for the same cu_seqlens object. The old path synced the stream at the first GDN layer of every extend (`.tolist()` in `prepare_chunk_indices`, the pageable `new_tensor([0])` in `prepare_chunk_offsets`). With the flag on, a request on CUDA cu_seqlens that wasn't planned raises.
  - `ARC_MM_NO_SYNC=1`: pixel features on CPU are first copied into pinned memory before going to the GPU (the pageable copy of a new 9.8 MB screenshot makes the host wait until the stream reaches it), and the attention max_seqlen of the Qwen3-VL vision encoder is computed from the host cu_seqlens instead of `.item()` on the device copy.

The value is that the target extend can now be put into a graph.

- **thinking length cap** (`ARC_THINK_BUDGET=<N>`, opt-in, unset by default = path unchanged; arc-forge `docs/research/think_budget_g4_20261011.md`): when a request's output reaches N tokens while thinking is still open, EAGLE v2 chain verify (`run_eagle_verify`, before eagle_sample) rewrites that request's verify rows to produce `\n</think>\n\n` + one non-whitespace token — exactly the chat template's rendering of this turn (`reasoning_content|trim` + `\n</think>\n\n` + content), so the next turn's QSA session replay and DFlash session park connect as usual. `speculative/arc_think_budget.py`:
  - One GPU state per req_pool slot, advanced by the accept result (under overlap `output_ids` lags one step behind, so it can't be relied on; no sync): while thinking, WAIT (the previous token was whitespace / half a UTF-8 character) / OK (text) / NLOK (text + a lone `\n`), then END, NN, DONE.   - `ARC_MAMBA_TRACK_HOST=1`
    - Scope: the mamba radix track of plain EXTEND under `extra_buffer`.
    - The original problem: computing the track plan reads data back from device to host, and these reads sync the stream. They include:
      - the scheduler's `.item()` once per request, and three pageable `torch.tensor(list, device=)`.
      - the backend's `mask.any()`.
      - boolean-mask indexing of the conv indices, and `clamp(0, qsl[-1] - 1)`. The latter is passed a 0-dim tensor, binds to the Scalar overload and triggers `.item()`.
      - 6 `.cpu()` in `_init_track_ssm_indices`.
      - GDN's `nonzero()`.

    - What the flag does:
      - The scheduler records the ping-pong position each request uses this time. `mamba_track_indices` is now built on the schedule stream by `stack`ing each request's ping-pong buffer and then `gather`ing, on the same stream and in order with every operation that writes these buffers.

The capture and replay batches of the prefill CUDA graph now both carry mirrors (see the runner change in the next item) and no longer raise.

      - value-by-value comparison with the old path on random batches, for both GDN and Mamba2.
      - device tensors placed on meta, so any host read raises. The old path serves as the positive control and does raise.
